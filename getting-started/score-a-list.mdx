---

You already keep lists somewhere. A Google Sheet, a Clay table, a CRM export. You do not need to move them into OpenNous. Keep the list where it is and call OpenNous for the one thing a spreadsheet cannot give you, a live ICP fit score and intent, computed against your own model and written into the revenue context graph.

The list stays yours. OpenNous owns the score. And because the score lands in the graph, every agent you run reads the same number through [`get_context`](/mcp/tools/get-context) and [`query`](/public-api/query), and the model sharpens from your own won and lost deals as you record outcomes.

<Note>
Scoring needs a model. Create one first with [`set_icp`](/mcp/tools/set-icp), or train it on real deals with [`POST /v2/icp/closed-deals`](/public-api/icp/train). Already score accounts your own way? See [Bring your own scorer](/getting-started/bring-your-own-scorer).
</Note>

## One verb

[`score`](/public-api/score) scores one row at a time, or up to 100 graph leads with `identifiers`. It accepts an email, a domain, a LinkedIn URL, or an entity UUID, and writes the result into the graph.

## Google Sheets

Add a `=NOUS(A2)` function to any column. In your sheet, open **Extensions → Apps Script**, paste this, and save.

```javascript
function NOUS(email) {
  const r = UrlFetchApp.fetch("https://api.opennous.cloud/v2/score", {
    method: "post",
    contentType: "application/json",
    headers: { Authorization: "Bearer YOUR_API_KEY" },
    payload: JSON.stringify({ identifier: email }),
    muteHttpExceptions: true
  });
  const j = JSON.parse(r.getContentText());
  if (j.scored) return `${j.icp.score} ${j.icp.tier} / intent ${j.intent.score}`;
  return j.reason || "n/a";
}
```

Then put `=NOUS(A2)` next to your email column and fill down. Each cell calls OpenNous, shows the score, and writes the judgment into the graph.

## Clay

Add an **HTTP API** enrichment column.

- **Method** `POST`
- **URL** `https://api.opennous.cloud/v2/score`
- **Header** `Authorization: Bearer YOUR_API_KEY`
- **Body** `{ "identifier": "{{Email}}" }`

Map `icp.score`, `icp.tier`, and `intent.score` from the response into columns. Every row now carries a live OpenNous score, and each call updates the graph.

## A whole list, or a weekly job

Send up to 100 rows per call with `identifiers`, and loop for a larger sheet. Run it on a cadence from n8n, Make, or a cron job to keep every score current.

```bash
curl -X POST https://api.opennous.cloud/v2/score \
  -H 'Authorization: Bearer YOUR_API_KEY' \
  -H 'Content-Type: application/json' \
  -d '{ "identifiers": ["sarah@acme.com", "tom@globex.io"] }'
```

For rows OpenNous does not have yet, send their attributes in `leads` instead. Up to 1000 are scored inline and nothing is written.

## Rows OpenNous does not know yet

A row only scores if OpenNous has facts to score on. A brand-new email with nothing behind it comes back as `unknown_identifier`, or `awaiting_enrichment` when OpenNous has the account but no facts to score on yet. Enrich those accounts first, then score them again. OpenNous never invents a score for an account it has no signal on.

## What you get back

| Field | Meaning |
|---|---|
| `icp.score` | ICP fit, `0` to `100` |
| `icp.tier` | `tier_1` / `tier_2` / `tier_3` / `not_icp`, the class that drives the play |
| `intent.score` | How warm the account is right now, `0` to `100`, decaying over time |
| `intent.band` | `Red-hot` / `Hot` / `Warm` / `Aware` / `Dormant` |

For the raw JSON shape, see the [`/v2/score`](/public-api/score) reference.
