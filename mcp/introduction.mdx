The MCP server gives your agent the Nous context graph as a focused set of tools — engineered, epistemics-tagged context, never raw rows. The agent also sets the workspace up itself. **Call `get_workspace_status` first.**

Runs **locally** via `npx` (Claude Code, Cursor, Codex, Claude Desktop) or **hosted** over HTTP at `https://mcp.opennous.cloud/mcp` (n8n cloud). Both hit the same graph, so a write through one shows in the other. For known-parameter calls, prefer the [REST API](/public-api/introduction).

## Get started

One command — installs the CLI, signs you in, and registers the MCP with your agent:

```bash
curl -fsSL https://api.opennous.cloud/install | sh
```

Then tell your agent **"set up my Nous workspace"**. It finds your ICP (or drafts one from your website) and syncs it. That's onboarding.

Already have the CLI, or prefer to run it yourself:

```bash
npx @opennous/cli init
```

`init` signs you in via the browser, saves a workspace key to `~/.nous/config.json`, and runs `claude mcp add` for you.

## Wire it up by hand

For other clients, run `npx @opennous/cli login` once (saves the key to `~/.nous/config.json`), then add Nous to your client's MCP config:

```json
{
  "mcpServers": {
    "nous": { "command": "npx", "args": ["-y", "@opennous/mcp"] }
  }
}
```

| Client | Where |
|---|---|
| **Claude Code** | `claude mcp add nous -- npx -y @opennous/mcp` |
| **Cursor** | `~/.cursor/mcp.json` |
| **Claude Desktop** | `~/Library/Application Support/Claude/claude_desktop_config.json` (macOS) · `%APPDATA%\Claude\claude_desktop_config.json` (Windows) |
| **Codex** | `~/.codex/config.toml` — TOML, see below |
| **Any MCP client** | its `mcpServers` block |

```toml
# Codex — ~/.codex/config.toml
[mcp_servers.nous]
command = "npx"
args = ["-y", "@opennous/mcp"]
```

<Note>
No `NOUS_API_KEY` needed once you've run `login` — the server reads `~/.nous/config.json`. To pin a specific key instead, add `"env": { "NOUS_API_KEY": "..." }` (create one at Settings → API Keys).
</Note>

<Note>
**Optional: the [Claude Code plugin](https://github.com/NousC/nous/tree/main/plugins/nous).** Adds hooks that make Claude reach for Nous automatically on GTM work. A power-up, not a requirement — the command above already gives you every tool. `/plugin marketplace add NousC/nous` then `/plugin install nous@nous-plugins`.
</Note>

## Hosted server (remote HTTP)

For clients that can't launch a local process (n8n cloud, any remote-URL client). Same tools, same graph. Authenticate per request with your API key as a Bearer token.

```
Endpoint   https://mcp.opennous.cloud/mcp
Auth       Authorization: Bearer YOUR_API_KEY
```

- **n8n cloud** — MCP Client Tool node → Transport `HTTP Streamable`, Endpoint the URL above, Auth `Bearer`.
- **Claude Code (remote)** — `claude mcp add --transport http nous https://mcp.opennous.cloud/mcp --header "Authorization: Bearer YOUR_API_KEY"`

## The daily loop

1. **Start a task** → `get_context` with the right `intent` for a ranked, budget-fit context block.
2. **Need the user's rules?** → `get_playbook` (voice, outreach, icp, positioning) — never `query`/`get_account` for this.
3. **Something happened** → `record` it. Nous derives the claims.
4. **Made something durable?** → `save_note` the brief or transcript onto the contact.
5. **End of session** → `attention` for what to work next.

<Note>**`record` vs `save_note`.** `record` logs that something *happened* (an email, a meeting) and Nous derives claims from it. `save_note` keeps the *document itself* (a brief, a transcript), append-only and dated. Use both.</Note>

## Environment

| Variable | Required | Default | Purpose |
|---|---|---|---|
| `NOUS_API_KEY` | if not signed in via CLI | — | Workspace key. Create at Settings → API Keys. |
| `NOUS_API_URL` | no | `https://api.opennous.cloud` | Override for self-hosted. |

Source lives at [`apps/mcp`](https://github.com/NousC/nous/tree/main/apps/mcp); each release ships to npm as `@opennous/mcp@<semver>`. Pin a version for reproducible installs: `npx -y @opennous/mcp@0.43.0`.
