title: "attach_list"
description: "Score a whole list you built somewhere else in one call. Nous creates the list, resolves every row, and scores each against your ICP model and intent."
---

Score a whole list you built somewhere else, a Google Sheet, a CRM export, a Clay table, in a single call. Nous creates a lead list, resolves each row to a person or company (deduped against everything already in the graph), and scores every row against your ICP model and current intent. The spreadsheet stays yours. Nous keeps the roster so the scores stay current and every other agent can read them.

Each row needs an email or a LinkedIn URL. Rows Nous does not know enough about yet come back as awaiting enrichment, so you know which ones to enrich first.

<Note>
`attach_list` needs a scoring model. Build one first with [`build_scoring_model`](/mcp/tools/build-scoring-model).
</Note>

## Parameters

| Name | Type | Required | Description |
|---|---|---|---|
| `rows` | object[] | ✓ | The list rows. Each needs an `email` or a `linkedin_url`. Max 200 per call |
| `name` | string | | Name for the new list. Omit only when passing `lead_list_id` |
| `lead_list_id` | string | | Add to an existing list instead of creating one |
| `source` | string | | Where the list came from, for example `google_sheet` or `crm_export`. Defaults to `external` |
| `import_duplicates` | boolean | | Force-insert rows already in the list. Defaults to `false` |

Each row accepts `email`, `linkedin_url`, `domain`, `company`, and `name`.

## Returns

A summary of what was ingested and scored, then the top-scoring rows:

```
Attached 200 rows to list 06167031-… — 187 new, 13 already in list.
Scored 142; 45 awaiting enrichment; 13 unresolved.

Top scored:
  sarah@acme.com — ICP 84 (tier 1) · intent 64 Warm
  jane@globex.io — ICP 79 (tier 1) · intent 40 Aware
  …

45 rows need enrichment before they can score. Run signal-scan or a lead builder on the list, then re-attach.
```

## What happens to each row

| Outcome | Meaning |
|---|---|
| **scored** | Resolved and scored. The ICP fit and intent are on the account |
| **awaiting enrichment** | Resolved, but Nous has no scoreable facts yet. Enrich, then re-attach |
| **unresolved** | No email or LinkedIn URL on the row, so it could not be added |

Rows are deduped against the workspace, so re-attaching the same sheet reuses existing records instead of forking duplicates. Scoring an already-scored row never stacks duplicate predictions.

## When to call it

- **You built a list somewhere else** and want the whole thing scored into the graph in one pass
- **On a cadence** over a sheet, so the roster and every score stay current
- **After enrichment** to re-attach the rows that were awaiting facts the first time

For a single row, use [`score`](/mcp/tools/score). For the full account behind a score, use [`get_context`](/mcp/tools/get-context).

## Backed by

`POST /v2/lead-lists/attach` — see the [HTTP reference](/public-api/leads/attach) for the raw JSON shape.
