Self-hosting runs the same code as [OpenNous Cloud](https://app.opennous.cloud), minus the private Cloud layer. See [Cloud vs self-host](/getting-started/cloud-vs-self-host) for the differences.

There are two ways to run it:

- **Bundled stack (default).** Everything runs in Docker on one server, including Postgres and auth. No Supabase account needed.
- **Bring your own Supabase.** The app containers run on your server and use a Supabase project for the database and auth.

## Prerequisites

- A Linux server with Docker and Docker Compose
- Node.js 18+ on the server, to generate keys
- An [Anthropic API key](https://console.anthropic.com). Extraction runs on it.
- Three DNS records pointing at the server: `app`, `api` and `mcp`

## Option 1: Bundled stack

{/* verify against GET-756 */}

The bundled stack runs these containers:

| Container | What it does |
|---|---|
| `postgres` | Postgres with pgvector. Holds the graph. |
| `postgrest` | REST layer over Postgres, used by the API |
| `gotrue` | Supabase Auth. Signs users in. |
| `api` | REST API, integrations, webhooks, automations |
| `worker` | Ingestion, extraction, scoring and scheduled jobs |
| `mcp` | Hosted MCP server at `https://mcp.yourdomain.com/mcp` |
| `frontend` | The web app, served by nginx |
| `caddy` | TLS and subdomain routing |

### 1. Clone

```bash
git clone https://github.com/NousC/opennous.git && cd opennous
```

### 2. Generate keys

```bash
node scripts/selfhost-keys.mjs
```

This generates the database password, JWT secret, API keys and `ENCRYPTION_KEY`, and writes them to the env file. Open the env file and set:

- `APP_DOMAIN`, `API_DOMAIN`, `MCP_DOMAIN`
- `ANTHROPIC_API_KEY`

Every variable is listed in the [environment reference](/installation/environment).

### 3. Start

```bash
docker compose -f docker-compose.selfhost.yaml up -d
```

Caddy requests TLS certificates once DNS resolves. The app is at `https://app.yourdomain.com` and the API at `https://api.yourdomain.com`.

Prebuilt images are published to GHCR (`ghcr.io/nousc/opennous-api`, `-worker`, `-frontend`, `-mcp`). {/* verify against GET-758 */}

## Option 2: Bring your own Supabase

Use this if you already run Supabase, or want a managed database. It uses `docker-compose.yaml`, which runs `api`, `worker`, `mcp`, `frontend` and `caddy`. The images are built from source on your server.

### 1. Clone and configure

```bash
git clone https://github.com/NousC/opennous.git && cd opennous
cp nous.env.example nous.env
```

In `nous.env`, set:

```bash
APP_DOMAIN=app.yourdomain.com
API_DOMAIN=api.yourdomain.com
MCP_DOMAIN=mcp.yourdomain.com

# Supabase → Settings → API
SUPABASE_URL=https://yourproject.supabase.co
SUPABASE_SERVICE_ROLE_KEY=eyJ...
SUPABASE_JWT_SECRET=          # recommended: verifies sessions locally
VITE_SUPABASE_URL=https://yourproject.supabase.co
VITE_SUPABASE_ANON_KEY=eyJ...

ANTHROPIC_API_KEY=sk-ant-...
ENCRYPTION_KEY=               # openssl rand -hex 32
SELF_HOSTED=true
```

### 2. Create the database

<Warning>
  Required before first boot. Without it the app starts, but nothing works.
</Warning>

In your Supabase project, open **SQL Editor** and run the full contents of [`supabase/schema.sql`](https://github.com/NousC/opennous/blob/main/supabase/schema.sql) once. It is the complete schema, including the `pgcrypto` and `vector` extensions. A fresh install does not run the files in `supabase/migrations/`. Those are for [upgrading](/installation/upgrading).

### 3. Turn on email sign-in

In Supabase, open **Authentication → Sign In / Providers** and enable **Email**.

### 4. Start

```bash
docker compose --env-file nous.env up -d --build
```

`--env-file nous.env` is needed: the frontend build and Caddy read their values from it. The first build takes a few minutes.

## Sign in

Open `https://app.yourdomain.com` and create an account. The first account becomes the owner.

Sign-in uses Supabase Auth. Email and password work without any mail setup. Invites, magic links and password resets need SMTP. {/* verify against GET-756: SMTP variable names for the bundled gotrue container */}

To close public sign-up after the first account, set `DISABLE_SIGNUPS=true` and restart. On Option 2, also turn off **Allow new users to sign up** in Supabase, since sign-up goes from the browser straight to Supabase.

## Connect your agent

```bash
npx @opennous/cli@latest init --url https://api.yourdomain.com
```

This signs you in against your instance, saves a key and the URL to `~/.nous/config.json`, and registers the MCP server with your agent. The `--url` is what points it at your instance instead of Cloud.

To configure the MCP server by hand instead, create a key under **Settings → API keys**:

```json
{
  "mcpServers": {
    "opennous": {
      "command": "npx",
      "args": ["-y", "@opennous/mcp"],
      "env": {
        "NOUS_API_KEY": "YOUR_API_KEY",
        "NOUS_API_URL": "https://api.yourdomain.com"
      }
    }
  }
}
```

Remote MCP clients can use the hosted endpoint on your instance, `https://mcp.yourdomain.com/mcp`, with the key as a Bearer header.

## Integrations

Integrations are connected per workspace in **Settings → Integrations**, mostly with the provider's own API key. A few need instance-level settings in the env file, for example LinkedIn (`UNIPILE_API_KEY`, `UNIPILE_DSN`) and Salesforce (`SALESFORCE_CLIENT_ID`, `SALESFORCE_CLIENT_SECRET`). See the [environment reference](/installation/environment).

## Logs

```bash
docker compose logs -f api
docker compose logs -f worker
docker compose logs -f frontend
```

On the bundled stack, add `-f docker-compose.selfhost.yaml` before `logs`.

## Stopping

```bash
docker compose down        # stop containers, keep data
docker compose down -v     # stop and delete volumes. On the bundled stack this deletes the database.
```
